## Bring the pieces of your work together

An application needs more than code. It needs a repository, a place to run, access to data, and people who can manage it. Railgrid brings those capabilities into a workspace so you can work across them from the console, CLI, or an AI assistant.

Start with the capability you need today. Add others as your workflow grows: connect a GitHub repository, provision a development environment, give an agent tools, or query a connected cluster.

## Follow a connected workflow

[Build an application using Databricks data](/docs/use/app-studio/databricks/) shows how the parts work together. Use App Studio to build the application, Code for its repository, Infrastructure for its runtime, and Databricks for access to an existing table. The guide covers the required connections and grants as well as the application work.

## How Railgrid fits your environment

A **hub** provides the shared control plane. **Workspaces** organize resources and access. **Providers** add capabilities such as App Studio, AI agents, and Edges. Your deployment determines which providers and external services are available.

Start with the Railgrid SaaS hub and choose a tutorial above; each guide lists its workspace prerequisites. To run Railgrid on your own infrastructure, see [Self-hosting](/docs/self-hosting/). Learn more about [how Railgrid works](/docs/get-started/what-is-railgrid/#how-railgrid-works).
